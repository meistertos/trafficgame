# Mind the Gap — prototype implementation plan

Source of truth: `docs/specs/traffic-prototype-spec.md`. The level editor (`docs/specs/level-creation-tool-spec.md`) is explicitly out of scope for these phases; the engine keeps a DOM-free core so the editor can import it later.

## Layout

```
game-proto/
  index.html                  entry point (ES modules, no build step)
  styles.css
  traffic-levels.json         authoritative level pack (authored from spec §5 tables)
  traffic-levels.schema.json  structural schema for the pack
  level-validation.json       generated by tools/headless-validation.mjs (report + pack hash)
  src/
    constants.js              tick rate, world, gap, vehicle types
    geometry.js               lane vectors, rects, swept-AABB collision math
    data.js                   pack parsing + structural/semantic validation (no deps)
    sim.js                    pure simulation: spawns, admission, following,
                              commitment, swept collisions, exits, outcomes, replay
    render.js                 Canvas 2D renderer + signal hit layout
    input.js                  pointer→world transform, keys, touch
    ui.js                     screens/HUD: select, preview, countdown, pause, results
    audio.js                  tiny WebAudio bleeps + persisted toggle
    main.js                   boot + fixed-step loop (120 Hz) + pause/hidden-tab logic
  tools/
    author-references.mjs     deterministic autopilot that derives referenceSolution windows
    headless-validation.mjs   node runner: all §7 engine checks, writes level-validation.json
```

## Phases

1. `phase-1-data-and-simulation.md` — pack + schema + pure sim; L1 deterministic replay.
2. `phase-2-collision-ambient-following.md` — swept collisions, ambient streams, following, downstream signals; L2–L4 references.
3. `phase-3-all-six-levels.md` — four-light and grouped-lane layouts, buses; all six references reproduce.
4. `phase-4-playable-ui.md` — full playable browser game (mouse/touch/keys, HUD, results, persistence).
5. `phase-5-validation-parity.md` — headless validation runner, outcome matrix, perturbation tolerance, `level-validation.json`.

## How to run (for testing)

Any static server from `game-proto/` works, e.g.:

```
cd game-proto && python3 -m http.server 8080
# open http://localhost:8080/
```

Headless engine validation (no browser):

```
node game-proto/tools/headless-validation.mjs
```

## Phase 7 — Phaser 4 front end (`./game`)

Re-implementation of the playable game in Phaser 4.2.1 + Vite. It reuses the engine and pack from
`game-proto` through Vite aliases (no copy of the rules), so the headless validator covers it.
Scenes: Boot (pack validation, generated textures) → Select → Play (preview, countdown, fixed 120 Hz
stepping, pause, results). See `game/README.md`.
